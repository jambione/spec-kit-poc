# Spec Kit POC: AI-Driven Development Lifecycle (AI-DLC)

A proof of concept showing how a team can run an **AI-driven development lifecycle** with
**GitHub Copilot** (agent mode) and **[GitHub Spec Kit](https://github.com/github/spec-kit)** on
a **.NET 8** codebase.

**The project being built:** *Story Verification Recordings*. When a developer finishes a user
story or defect, they record what they expect to happen with the **Playwright recorder**. The recording is saved as a JSON
verification file, and a Playwright runner replays it against the environment that has their
code. See the [brief](docs/demo/feature-brief.md).

> **AI drafts, humans decide.** Copilot writes the spec, plan, tasks and code; named people
> approve each step at a gate; Git records the whole trail.

## The flow

| Phase | Copilot Chat command | Output | Gate |
|---|---|---|---|
| Foundation | `/speckit-constitution` | `.specify/memory/constitution.md` | Tech Lead |
| Inception | `/speckit-specify` → `/speckit-clarify` | `specs/NNN-*/spec.md` | **G2** PO + TL |
| Construction | `/speckit-plan` | `plan.md`, `data-model.md`, `contracts/` | **G3** Architect |
| | `/speckit-tasks` → `/speckit-analyze` | `tasks.md` | **G4** TL |
| | `/speckit-implement` (→ `/speckit-converge`) | `src/`, `tests/` | **G5** PR review + CI |
| Operations | CI/CD pipeline | build, deploy | **G6** Release owner |

## Quick start

Prerequisites: VS Code + GitHub Copilot Chat (agent mode), .NET 8 SDK, Python 3.11+, Git.

```bash
git clone <this repo> && cd spec-kit-poc
code .
```

In **Copilot Chat → Agent mode**, type `/speckit` to see the commands, then follow
[`DEMO-SCRIPT.md`](docs/demo/DEMO-SCRIPT.md) from step 3.

To upgrade or re-initialize Spec Kit (optional):
```bash
uv tool install specify-cli    # POC pinned at specify-cli 1.4.0
specify check
```

## How gates are enforced

- **`scripts/check-gates.sh`** (runs in CI on every PR): if `src/` changed, the branch must be a
  Spec Kit feature branch with `spec.md`, `plan.md` and `tasks.md`, and no unresolved
  `[NEEDS CLARIFICATION]` markers. `bugfix/*` and `hotfix/*` branches are exempt. Run it locally
  with `bash scripts/check-gates.sh origin/main`.
- **Human approvals** come from PR reviews. To make them mandatory, turn on branch protection
  for `main` in GitHub: require 1+ approving review and require the `ai-dlc-gates` and
  `dotnet-build-test` checks to pass.

## AI agents

**GitHub Copilot (agent mode) is the default and the focus of this POC.** Spec Kit itself is
agent-neutral, so other agents are an option:

```bash
specify integration list
```

This shows the supported agents and what's installed. In Spec Kit 1.4.0, Copilot isn't marked
"multi-install safe", so to try another agent, switch on a separate branch rather than
installing it alongside Copilot:

```bash
specify integration switch <key>
```

The constitution, templates, specs and the review extension stay the same. Only the agent's
command files change.

## Quality loop: Review, Attack & Fix extension

`extensions/review/` (installed in `.specify/extensions/review/`) adds the step Spec Kit lacks
after `/speckit-implement`: `/speckit-review-code` (critic), `/speckit-review-attack`
(adversary), `/speckit-review-rule` (developer rulings), `/speckit-review-fix` (fixer) and
`/speckit-review-audit` (final check against the spec). Defects must be proven with failing
tests, and CI blocks the PR while any BLOCKER/MAJOR finding is unresolved. See
[`extensions/review/README.md`](extensions/review/README.md).
