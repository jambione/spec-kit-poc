# Reference Example: what good Spec Kit output looks like

This folder is a **hand-written reference** of what the Spec Kit steps should produce for the POC
project, *Story Verification Recordings*. Use it to:

- **Calibrate reviews.** At G2–G4, compare what Copilot generated against this. Is the spec
  testable? Does the plan pass the Constitution Check? Does every requirement have a task?
- **Rescue the demo.** If Copilot goes off track live, walk through these files instead.
- **Show the team the target** before they run the commands themselves.

> **It is not the real spec.** The real one is generated by `/speckit-specify` into
> `specs/001-…/` and reviewed at the gates. This example lives under `docs/` on purpose, so it
> doesn't trigger the CI gate check or clash with Spec Kit's feature numbering.

## Assumptions used in place of the project context

`docs/poc/PROJECT-CONTEXT.md` isn't filled in yet, so this example uses the assumptions below.
Each one is marked **(assumed)** where it appears. Your real run replaces them with your answers.

| Context item | Assumed for this example |
|---|---|
| Target application | A browser-based web app, run locally at `http://localhost:5000` |
| Work item ID format | Configurable pattern; examples use `PROJ-123` |
| Environments | `dev`, `qa`, `staging`, each with a base URL in settings or an environment variable |
| Sign-in | Username and password form; password supplied at run time as a secret. SSO via a pre-saved Playwright storage state |
| Test data | Supplied at run time as named variables; no data seeding in v1 |
| Pipeline | GitHub Actions |
| Runner language | .NET 8 with `Microsoft.Playwright` |
| Browsers | Chromium required; Firefox and WebKit optional |
| Recorder output | Playwright recorder in **JSONL** mode, converted to the team's JSON format (see `research.md`) |
